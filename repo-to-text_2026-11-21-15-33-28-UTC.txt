<content full_path="src\content\docs\applications\automation.md">
---
title: Role Automation & Triggers
description: Automate role assignments and handle departed applicants.
---

Stop manually updating Discord roles every time an application is processed. TicketForge can handle role assignments, edge cases, and staff reminders automatically. 

![Automation Options](/images/applications/automation_page.png)

Navigate to **Edit Application > Automation** to configure these settings.

## 1. Resolution Actions

You can instruct the bot to add or remove specific Discord roles based on the exact status of the application. 

* **On Submit:** Executes the moment a user finishes the form (e.g., adding an "Applicant" role so they know their form went through).
* **On Accept:** Executes when a staff member approves the application (e.g., adding the "Trial Mod" role and removing the "Applicant" role).
* **On Deny:** Safely revert or remove roles if the user is rejected.

![Resolution Actions](/images/applications/resolution_actions.png)

:::caution[Permission Check]
For the bot to assign these roles, the **TicketForge** role must be placed **higher** in your Discord Server Settings than the roles you select here.
:::

---

## 2. Auto-Deny Missing Users *(Premium)*

Sometimes users apply for a position and then leave the server before your staff has a chance to review their submission. 

If **Auto-Deny Missing Users** is enabled, TicketForge will automatically detect if the applicant is no longer in the Discord server. It will instantly mark their pending application as "Denied" and log it, keeping your staff queue clean from ghost applications.

![User Leave Handling](/images/applications/user_leave.png)

---

## 3. Inactivity Notifier *(Premium)*

Never let an application slip through the cracks. The **Inactivity Notifier** will automatically ping your staff if an application sits in the "Pending" state for too long.

### Configuration
1. **Notification Channel:** The text channel where the reminder ping should be sent (usually a private staff channel).
2. **Roles to Ping:** Select your Management or Reviewer roles.

Even if a user's previous application was reviewed and denied, you might not want them instantly applying again.

    * *Note:* You can also set specific time limits on individual questions via the **Questions** tab.
2. **Auto-Submit on Timeout:** *(Premium)* If the timer runs out, you can automatically submit whatever answers the user *did* finish instead of immediately discarding the application.

* **Regex Validation:** *(Premium)* Require the answer to match a specific mathematical pattern. Perfect for forcing users to enter valid email addresses, URLs, or specific ID formats.

![Text Answer Config](/images/applications/text_config.png)

### Multiple Choice
Provide users with a list of predefined options to choose from.
* **Add Choices:** Click **Add Choice** to create new options. You can have up to 5 choices (Free) or 25 choices (Premium) per question.
* **Min / Max Selections:** This setting dictates how the question behaves:
    * *Radio Buttons (Single Choice):* Set Min to 1 and Max to 1. The user can only pick one answer.
    * *Checkboxes (Multiple Choice):* Set Max to a number greater than 1. The user can select multiple options simultaneously.

![Multiple Choice Config](/images/applications/choice_config.png)

### Image Upload *(Premium)*
Requires the user to provide an image attachment. 
* **Best for:** Age verification, building portfolios, or providing screenshot proof for ban appeals. 
* *Note:* Users will be prompted to upload a file directly from their device or paste an image URL.

![Image Upload Config](/images/applications/image_config.png)

---

## 4. Time Constraints *(Premium)*

Want to run a timed test or a strict questionnaire where users can't spend hours Googling answers? You can enforce a strict **Time Limit** on individual questions.

1. Toggle **Time Limit** to ON at the bottom of the question configuration.
2. Set the **Duration** (e.g., 60 seconds).
3. When the user reaches this question, a visible countdown timer will appear. If it hits zero, the question is locked, and they are forced to move to the next one.
</content>

title: Variables & Dynamic Placeholders

You can use dynamic variables in your **Messages**, **Embeds**, and **Channel Names**. The bot will automatically replace them with real data when the message is sent, the channel is created, or the application is processed.

![Variable Options](/images/applications/placeholders.png)

---

## 1. Context: User vs. Author

Before using variables, it is crucial to understand the difference between the **User** and the **Author** in TicketForge.

* **The User (`{user_*}`)**: The person who *owns* the object. 
    * In a Ticket, this is the person who opened the ticket. 
    * In an Application, this is the applicant.
* **The Author (`{author.*}`)**: The person who *triggered* the current action. 
    * If the user clicks "Start Application", the user is the author. 
    * If a Staff member clicks "Accept", the staff member is the author.

---

## 2. Application Placeholders

These variables are specifically available within the **Application Editor > Messages** section (e.g., Application Received, Accepted/Denied notices).

### Application Data
| Placeholder | Description |
| :--- | :--- |
| `{application.name}` | The name of the application panel (e.g., "Staff App"). |
| `{application.results}` | The fully formatted list of questions and answers submitted by the applicant. |
| `{application.conclusion}` / `{conclusion}` | The final status (e.g., "Accepted" or "Denied"). |
| `{application.reason}` / `{reason}` | The reason provided by staff when accepting/denying. |
| `{deadline}` | The calculated deadline time (if a time limit was set). |

### Review & Staff Actions
Used in Review Results and DM Notifications.

| Placeholder | Description |
| :--- | :--- |
| `{review_action}` | The action in lowercase (e.g., "accepted" or "denied"). |
| `{review_action_title}` | The action in title case (e.g., "Accepted" or "Denied"). |
| `{review_action_time}` | The Unix timestamp when the review was completed. |
| `{review_reason}` | The sanitized reason shown on the staff review result. |
| `{application.handled_by}` / `{handled_by}` | The staff member who reviewed the application. |
| `{reviewer}` | Mentions the staff member who reviewed the application. |
| `{reviewer.name}` | The reviewing staff member's username. |
| `{reviewer.icon}` | URL of the reviewing staff member's profile picture. |

---

## 3. Ticket Placeholders

These variables are available within the **Panel Editor > Messages** section for standard Tickets.

### General Ticket Info
| Placeholder | Description |
| :--- | :--- |
| `{ticket}` | Mentions the ticket channel (clickable link). |
| `{ticket.name}` | The name of the ticket channel. |
| `{ticket.id}` | The unique channel ID of the ticket. |
| `{ticket_opener}` | Mentions the user who opened the ticket. |
| `{ticket_closer}` | Mentions the user who closed the ticket. |
| `{close_reason}` / `{ticket.close_reason}`| The reason provided when the ticket was closed. |
| `{transcript.users}` / `{transcript_users}`| List of users involved in the ticket transcript. |

### Claim Status
| Placeholder | Description |
| :--- | :--- |

## 6. Advanced Logic (Modifiers)

You can append modifiers to almost any variable to change how it is formatted or displayed. 
**Syntax:** `{variable?modifier}`

| Modifier | Alias | Example | Result / Description |
| :--- | :--- | :--- | :--- |
| **Uppercase** | `?uc` | `{user_name?uppercase}` | `JOHN` |
| **Lowercase** | `?lc` | `{user_name?lowercase}` | `john` |
| **Max Length** | `?ml=X` | `{ticket.id?maxLength=5}` | `12345` (truncates if exceeded) |
| **Pad Left** | `?pl=X` | `{count?padLeft=4}` | `0005` (adds leading zeros) |
| **Pad Right** | `?pr=X` | `{count?padRight=4}` | `5000` (adds trailing zeros) |
| **Fallback** | `?fb=Text`| `{claim.user?fallback=Unclaimed}` | Displays "Unclaimed" if variable is empty. |
| **Not Fallback** | `?nfb=Text`| `{claim.user?nfb=Claimed!}` | Displays "Claimed!" *only* if the variable contains data. |
| **Math** | `?m=op` | `{count?math=+1}` | Performs algebraic operations (`+`, `-`, `*`, `/`). |
| **Clean** | *(None)* | `{create.form_0?clean}` | Removes backticks to prevent markdown breaking. |
| **Random Min** | `?rmin=X`| `{random?rmin=10}` | Sets the minimum bound for a random number. |
| **Random Max** | `?rmax=X`| `{random?rmax=100}` | Sets the maximum bound for a random number. |

Common issues and remediation steps.

## Interaction Failures ("Thinking..." / "Failed")

If buttons or slash commands fail to respond:
1. **Channel Permissions:** Confirm `TicketForge` has `View Channel`, `Send Messages`, and `Embed Links` in that channel.

## User Cannot View Their Ticket

1. **Category Overrides:** Confirm category permissions allow the bot to manage channel overrides.

If uploaded custom bot avatars or banners revert:
* Verify images are under **8MB**.
* Ensure images use supported file formats: **PNG**, **JPEG**, or **GIF**.

A **Panel** is the interface your users interact with on Discord to open tickets. TicketForge allows you to create multiple panels for different purposes (e.g., "General Support", "Billing", "Reports").

![Dashboard Home](/images/creating-panel/login.png)

You can also navigate to this page by clicking on your profile and then "Servers".

1. Click on your **Profile Picture** in the top right corner to open the menu.
2. Select **Dashboard** from the dropdown menu.

![Server List](/images/creating-panel/select_server.png)

3. You will see a list of your Discord servers:

### Component Block Types

| Block Type | Description | Allowed Placement |
| :--- | :--- | :--- |
| **Container** | Groups elements inside a panel with an optional left accent color bar. | Root level only |
| **Section** | Split-column layout: content on the left, an accessory (image or button) on the right. | Root or inside a Container |
| **Text Display** | Markdown block. Supports `**bold**`, `*italics*`, `### headers`, code blocks, and links. | Root, Container, or Section |

| **Select Menu** | Interactive dropdown anchor populated at runtime (e.g., department escalation). | Root or inside a Container |

---

### Structural Limits & Nesting Rules

To ensure messages render reliably within Discord's gateway constraints, the editor enforces these rules:

1. **Hierarchy Limits:**
   * **Root Blocks:** Maximum of **9 top-level blocks**.
   * **Total Components:** Maximum of **36 total components** (counting all nested children).
   * **Text Budget:** Maximum of **4,000 characters** across all text fields, labels, and URLs.
2. **Container Isolation:**
   * A **Container** cannot be placed inside another Container.
3. **Section Restrictions:**
   * A **Section** can hold text and an accessory (image or button). It cannot contain another Section or a Container.
4. **Mobile Responsive Stacking:**
   * If a Section contains a button accessory, the live bot and preview will automatically stack the button below the text on mobile devices and narrow viewports.

---

### Smart Interaction & Action Safeguards

When working with action buttons (such as *Close Ticket*, *Claim*, or *Escalate*):

* **Automatic Action Syncing:** When you change your panel layout style (e.g., from *Single Button* to *Select Dropdown* or *Multi-Panel*), the builder automatically synchronizes required action buttons and select anchors into your V2 layout.
* **Orphan Protection:** If you delete a Container that held action buttons, the builder **salvages the action buttons** and moves them into another container so you never break ticket functionality by accident.
* **One-Click Embed $\rightarrow$ V2 Conversion:** Switching an existing Embed (V1) message to Components (V2) automatically converts your titles, fields, descriptions, and thumbnails into styled V2 text blocks and containers.

:::note[Token Lifetime]

## Configuration

Navigate to the **Commands** tab in the sidebar. You will see a list of all available bot commands.

### Command Settings

Click on any command to edit its permissions:

1. **Enable Command:** Master toggle. If OFF, the command acts as if it doesn't exist.
2. **Support Team Only:** Restricts usage to users who have a role designated as "Support" in any of your panels.
    * _Admin Commands (e.g., `/setup`, `/purge-tickets`) are restricted to Administrators automatically._

### Scope Restrictions

You can fine-tune where commands work:

* **Allowed Channels:** The command will *only* work in these channels.
* **Blocked Channels:** The command will work everywhere *except* these channels.
* **Allowed Roles:** Only these roles can use the command.
* **Blocked Roles:** These roles are specifically prevented from using the command.

title: Security & Anti-Alt Threat Engine
description: Deep browser telemetry, threat scoring, VPN/Tor blocking, and alt-account detection.

![Web Verification Portal](/images/verification/security.png)

The **Web Security Engine** operates as an intelligent risk-scoring firewall. When members verify via browser, TicketForge analyzes network reputation, browser authenticity, and device telemetry to prevent raids before they happen.

---

## 1. Core Security Policy

Navigate to **Verification > Security & Anti-Alt**:

### Enforcement Modes
* **Enforce (Block):** Actively blocks users whose cumulative risk score exceeds your configured threat threshold, presenting an **Access Denied** notice.
* **Monitor Only:** Allows all users through while silently flagging suspicious telemetry and recording incident reports into your **Audit Log Channel**.

### Threat Threshold (1–100)
The cutoff score required to trigger enforcement. If a user's combined risk signals exceed this number, their session is blocked.

| Preset Profile | Threshold | Intended Environment |
| :--- | :--- | :--- |
| **Relaxed** | `85` | Large public gaming servers; only catches script-driven headless bots and obvious alts. |
| **Recommended** | `70` | Default balanced defense; blocks throwaway alts, devtool tampering, and suspicious sessions. |
| **Protective** | `55` | High-security or sensitive communities; strictly penalizes private browsing, Brave shields, and multi-accounts. |

---

## 2. Immediate Pre-Score Blocks

You can configure immediate, zero-tolerance denials that block users before threat scores are even calculated:

| Guard | What It Detects | Why It Protects |
| :--- | :--- | :--- |
| **Block VPN / Proxy / Tor** | Datacenter IP addresses, public proxies, and Tor exit nodes. | Stops ban evaders and coordinated raid bots operating through masked IPs. |
| **Block Identity-Hiding Browsers** | Browsers configured to randomize fingerprints, spoof headers, or strip WebRTC. | Prevents automated spoofing software from forging fresh browser sessions. |
| **Block Developer Tools** | Browser DevTools console actively open during verification. | Blocks attackers attempting to reverse-engineer verification network payloads. |
| **Block Incognito / Private Mode** | Private browsing sessions across Chrome, Safari, Firefox, Edge, and mobile WebViews. | Ensures device storage can reliably detect duplicate alt accounts. |

---

## 3. Blocked Countries (Geofencing)

*(Premium Feature)*

Block incoming connections from specific geographic regions:
1. Select countries from the searchable country picker (e.g., `Netherlands (NL)`, `Russia (RU)`, `China (CN)`).
2. Users originating from blocked country IP ranges are denied immediate access prior to scoring.

---

## 4. Threat Score Builder

Customize the exact point weight contributed by each detected signal:

| Risk Signal | Default Points | Detection Method |
| :--- | :--- | :--- |
| **VPN / Proxy / Tor Node** | `+40` | Real-time ASN and datacenter IP threat intelligence. |
| **Likely Alt Account** | `+40` | Device fingerprint strongly matches a previously verified Discord account on the server. |
| **Possible Alt Account** | `+20` | Secondary hardware/network parameters overlap with an existing account. |
| **Bot-Like Behavior** | `+40` | `navigator.webdriver` flags, synthetic mouse movements, or programmatic DOM injection. |
| **Unusual Behavior** | `+30` | Form submitted faster than human thresholds (<1.2 seconds) or without input events. |
| **Identity-Hiding Browser** | `+30` | Browser masking headers or spoofing canvas/WebGL signatures. |
| **Incognito Mode** | `+15` | Browser storage quota and filesystem API restrictions. |
| **Developer Tools Open** | `+15` | Viewport dimension variance analysis. |
| **Suspicious Session (High)** | `+40` | Multiple conflicting hardware/timezone/locale indicators. |
| **Suspicious Session (Moderate)** | `+20` | Minor telemetry divergence from standard operating systems. |

import { Badge } from '@astrojs/starlight/components';

The **Server Welcomer** module automates your community's onboarding experience. Greet newcomers with dynamically rendered welcome cards, assign starter roles, send welcome DMs, track departing members, and celebrate member milestones.

## 1. Control Deck & Quick Actions

At the top of the **Welcomer** editor, the Control Deck provides instant diagnostics and testing tools:

### Welcomer Health Badge
The live **Health Status** indicator continuously validates your configuration against your Discord server:
* **🟢 Healthy:** All enabled outputs, channels, and roles are properly configured.
* **🟡 Warnings:** Non-critical configuration gaps (e.g., system is disabled, system is active with no enabled outputs, or milestones are enabled without any threshold rules).
* **🔴 Critical:** Blocking issues such as a deleted destination channel, missing `View Channel` / `Send Messages` bot permissions, or an auto-assign role positioned higher than the bot's role.

Click any item inside the Health dropdown to jump directly to the setting that needs fixing.

### Test Welcome
Click **Test Welcome** to dispatch a live mock welcome message—complete with your rendered welcome card—to any channel in your server.

![Send Test Welcome Modal](/images/welcomer/test_welcome.png)

* You can target a private staff channel to preview layout and copy changes without pinging members.
* If you have unsaved edits in the editor, **Test Welcome** saves them automatically before dispatching.
* Protected by a **30-second cooldown** per server to prevent channel spam.

### Reset Defaults
Restores all welcome cards, auto-assigned roles, message embeds, and milestone rules back to factory defaults.

---

## 2. General Settings

Navigate to **Welcomer > General & Card** to configure core module behavior:

![Welcomer General Settings](/images/welcomer/general_settings.png)

| Setting | Description | Default |
| :--- | :--- | :--- |
| **Enable Welcomer System** | Master switch for the entire welcomer module (channel welcomes, DMs, auto-roles, leave notices, and milestones). | `Disabled` |
| **Wait for Server Verification** | Delays channel welcomes, DM welcomes, and join role assignments until the user passes TicketForge's **Verification** check. | `Disabled` |
| **Ignore Bot Accounts** | Prevents sending welcome messages or assigning roles when a Discord bot is added to the server. | `Enabled` |

:::tip[Verification Interlock]
If you use TicketForge's [Verification System](/verification/setup/), enable **Wait for Server Verification**. New members won't be welcomed in general chat until they prove they are human—keeping your welcome channel free of unverified bots and raid accounts.
:::

---

## 3. Auto-Assign Roles

Automatically grant starter roles (such as `@Member` or `@Community`) when a user joins your server—or immediately after they pass verification if **Wait for Server Verification** is enabled.

### Security & Role Hierarchy Safeguards
To protect your server against privilege escalation:
* **Hierarchy Check:** The **TicketForge** bot role must sit **higher** in **Server Settings > Roles** than every role selected in **Roles to Assign**.
* **Dangerous Permissions Blocked:** TicketForge automatically blocks assigning `@everyone` or roles with dangerous administrative permissions (`Administrator`, `Manage Server`, `Manage Roles`, `Manage Channels`, `Ban Members`, or `Kick Members`).

---

## 4. Built-In Raid & Anti-Spam Protections

The Welcomer service includes automatic safeguards to keep your server and bot performance protected during raids:

* **Raid Surge Shield:** If a server experiences a sudden join surge (**8 or more joins within 5 seconds**), the Welcomer automatically engages a **90-second lockdown**, suppressing high-cost card rendering and welcome dispatches until traffic stabilizes.
* **New-Account DM Protection:** To comply with Discord anti-spam rules, **Welcome DMs** are automatically skipped for newly created Discord accounts younger than **60 minutes**.
* **In-Discord Setup (`/setup`):** You can also toggle welcomer modules, select channels, assign roles, and edit basic messages directly inside Discord by running `/setup`.
